# ADR-007 — Separar evidencia de mercado, pricing y precio máximo de compra

## Contexto

Las ideas originales diferenciaban tres preguntas que la planificación había agrupado bajo «precio»:

- ¿cuánto parece valer este producto en el mercado?;
- ¿a cuánto conviene ofrecerlo según el objetivo de venta?;
- ¿cuánto puedo pagar como máximo para cumplir la economía requerida?

La mediana de precios publicados no responde por sí sola las tres preguntas. Confundirlas produciría falsa precisión, especialmente cuando sólo existen observaciones `ASKING`.

## Decisión

COIE utilizará tres contratos históricos, trazables y versionados:

### `MarketPriceEstimate`

Describe evidencia observable. Conserva producto, mercado, condición, `priceType`, moneda, fecha de corte, ventana, definición de comparables, estadísticas, exclusiones, confianza, cobertura, inputs y versión.

`ASKING` y `SOLD` generan cohortes y estimaciones separadas. Una mediana `ASKING` no se denomina automáticamente «Market Value» ni valor realizable.

### `PricingRecommendation`

Responde cómo vender y puede producir escenarios:

```text
QUICK
TARGET
PREMIUM
```

Cada escenario conserva canal, precio recomendado opcional, velocidad esperada opcional, evidencia, supuestos, confianza, cobertura y estado de calibración.

`QUICK` requiere ventas/velocidad observadas o un proxy etiquetado y versionado. `PREMIUM` requiere evidencia de diferenciación. Si falta soporte, el precio permanece `unknown`.

### `MaximumBuyPrice`

Responde cuánto puede pagarse como máximo para una oportunidad `RESALE`:

```text
MaximumBuyPrice =
  ExpectedSalePrice
  - SellingCosts
  - AcquisitionIndependentCosts
  - MinimumRequiredContribution
  - RiskReserve
  - HoldingCapitalReserve
```

La ejecución conserva escenario seleccionado, costos, contribución requerida, reservas, gates, supuestos, inputs y versión. Si falta un costo crítico, no se calcula cero ni se inventa un umbral.

Ninguno de estos resultados publica, compra, negocia o asigna capital automáticamente.

## Alternativas consideradas

### Usar la mediana como precio de mercado, venta rápida y umbral de compra

Descartada porque cada salida tiene una semántica y evidencia distinta.

### Ocultar outputs sin datos suficientes

Descartada. Se mostrarán como `unknown/not computed` junto con el motivo y la evidencia necesaria.

### Permitir que un LLM decida precios

Descartada. La IA puede extraer o explicar; los cálculos, gates y versiones son deterministas.

## Consecuencias

- el shell Foundation debe llamar a su cifra actual «mediana de precios pedidos»;
- `MarketPriceEstimate`, `PricingRecommendation` y `MaximumBuyPrice` evolucionan de forma separada;
- el scoring consume resultados, pero no sustituye ninguno;
- el benchmark debe distinguir exactitud estadística y utilidad comercial.

## Criterio de revisión

Revisar las reglas y escenarios sólo después de contar con resultados reales suficientes para calibrarlos.
