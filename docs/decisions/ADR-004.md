# ADR-004 — Stack e interfaz web inicial

## Contexto

COIE necesita un esqueleto reproducible que funcione localmente antes de disponer de cuentas de Supabase y Vercel. El usuario eligió combinar el dashboard operativo A con el detalle analítico B.

## Decisión

- Aplicación web única en la raíz del repositorio.
- Next.js con App Router, React y TypeScript.
- Tailwind CSS como herramienta disponible, con CSS del proyecto para el shell inicial.
- PostgreSQL administrado mediante Supabase como persistencia objetivo.
- Adaptador DEMO sin red durante Sprint 0; la UI y el dominio dependen de puertos, no de Supabase.
- Vitest para pruebas unitarias; Playwright se incorpora cuando el flujo interactivo lo requiera.
- Desarrollo local primero y Vercel como destino de despliegue futuro.
- Diseño A+B: listado operativo en la pantalla principal y detalle analítico por oportunidad.

## Alternativas consideradas

### Monorepo o servicios separados

Descartada porque añadiría coordinación sin una necesidad medible.

### Supabase local con Docker desde Foundation

Descartada porque Docker no es necesario para validar contratos y todavía no existe un proyecto Supabase.

### Bloquear el desarrollo hasta crear cuentas externas

Descartada mediante el adaptador DEMO y fixtures reproducibles.

## Consecuencias

- `pnpm dev` y `pnpm check` deben funcionar sin credenciales ni red después de instalar dependencias.
- La integración Supabase se añadirá como adaptador, sin trasladar reglas de dominio a la base de datos o la UI.
- No se utilizarán fuentes web remotas durante el build.

## Criterio de revisión

Revisar si aparecen requisitos de escala, ejecución en segundo plano o integraciones que no encajen en una aplicación web única.
