# ADR-009 — Persistencia local DEMO append-only para MVP-A1

## Contexto

MVP-A1 necesita demostrar carga manual, idempotencia, histórico y materialización de `MarketPriceEstimate` antes de disponer de Platform Access. El proyecto Supabase ya existe, pero [[ADR-008]] difiere Auth/RLS y prohíbe operar datos comerciales reales multiusuario sin aislamiento.

El fixture versionado no debe mutarse en runtime y un singleton en memoria no sobrevive reinicios ni garantiza que una Server Action y una página lean el mismo estado.

## Decisión

- Incorporar un almacén JSON local, versionado y validado, en `.data/demo-evidence.json`.
- Mantener `fixtures/demo/nk150-resale.json` como semilla inmutable.
- Realizar cada importación mediante una transacción en memoria, validación completa y escritura atómica temporal + rename.
- Serializar escrituras dentro de un único proceso y registrar recibos, `CaptureRun`, conteos e idempotencia.
- Conservar el vendedor o el valor explícito `UNKNOWN` dentro de los parámetros inmutables del recibo mientras el perfil Foundation mantenga el listing `0.1.0`.
- Persistir listings, snapshots, observaciones y `MarketPriceEstimate` sin sobrescribir el histórico.
- Ignorar `.data/` en Git y mantener todo el flujo como `DEMO`, `MANUAL_USER_ENTRY`, sin red ni URLs reales.
- Acceder al almacén mediante un puerto para sustituirlo posteriormente por Supabase/PostgreSQL.

## Alternativas consideradas

### Mutar el fixture del repositorio

Descartada porque mezclaría datos runtime con fixtures reproducibles y ensuciaría Git.

### Persistencia únicamente en memoria

Descartada porque no sobrevive reinicios y puede divergir entre bundles de Next.js.

### Activar Supabase sin Auth/RLS

Descartada porque expondría una superficie de escritura sin el aislamiento definido en [[ADR-005]] y [[ADR-008]].

## Consecuencias

- El flujo manual puede demostrarse localmente y conserva histórico entre reinicios.
- `pnpm check` continúa funcionando sin credenciales ni red.
- El almacén no es apto para Vercel, varios procesos ni datos reales.
- La carga queda deshabilitada en producción salvo habilitación explícita; esa habilitación no sustituye autenticación.
- La migración futura a Supabase implementará el mismo puerto y requerirá Auth/RLS antes de datos reales multiusuario.

## Criterio de revisión

Reemplazar este adaptador al activar `AU-001`, desplegar en Vercel, ejecutar más de un proceso o incorporar cualquier dato comercial real.
